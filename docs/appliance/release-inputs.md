# Appliance V1 release inputs

The [release lock](../../appliance/releases/v1.lock.json) records reviewed official inputs as of 11 October 2026. It is an **unqualified base candidate**, not a bootable appliance release. The working machine is an ARM Mac without an x86-64 KVM runner or the target two-port hardware. Input provenance, unit checks and source inspection cannot establish installation or network safety.

`release_id` is `appliance-v1-base-20261011`; `adapter_id` is `pve-9-2-1`. Each byte limit equals the exact expected file size, so extra bytes fail verification. A downloaded input must match both size and digest before use. Compressed and expanded identities are distinct. The output bundle requires its own manifest; none of these hashes identifies an assembled appliance ISO.

## Probe and Linux role base

`probe-image` and `linux-base` intentionally refer to the same immutable vendor bytes. They are separate capability records and must create separate VM disks and local seeds. A build may deduplicate immutable storage by digest, but must never reuse a running VM or enrollment state across roles.

The [Ubuntu package manifest](https://cloud-images.ubuntu.com/releases/noble/release-20260926/ubuntu-24.04-server-cloudimg-amd64.manifest) lists `bind9-dnsutils`, `bind9-host`, `curl`, `iproute2`, `netcat-openbsd`, `openssl`, `python3`, `systemd-timesyncd` and `tcpdump`. This supports choosing it as the neutral probe input; it does **not** prove these tools work in the assembled appliance. The [probe preparation commands](probe.md) generate a private local NoCloud seed with console access, stable NIC mapping and site-specific networking, and disable package upgrades, package downloads and automatic enrollment. Console credentials must be unique per local instance and never embedded in the reusable image.

Qualify offline console login, actual virtual disk geometry, DNS queries, explicit NTP service checks, HTTPS validation and known listening endpoints. Time synchronization alone does not prove that an NTP server is reachable or correct. The probe must start without role provisioning or an Internet download. Its disposable disk must contain no persistent client/controller/relay identity. Seed/provisioning contract tests now exist; real guest startup and packet checks remain outstanding.

The `tailscale`, `headscale` and `derper` role binaries and their complete offline provisioning inputs remain explicitly missing. Role builds must refuse those capabilities until actual reviewed inputs are added. Their absence does not justify fabricating hashes, silently installing the latest package, or calling the base candidate complete V1.

## Exact ISO adapter

The implementation now inspects the complete verified 9.2-1 ISO rather than inferring its layout from source alone. The live root overlays the installer filesystem on the base filesystem. Python 3.13.5 and its standard library are in the base layer; the auto-installer is in the installer layer. The installer assistant is absent and is not a runtime/build dependency of this adapter.

The shipped launcher matches SHA256 `7a5be4ff18f286b9216811a6216e3ddd098d49206d4c900192c75b3c89b74d7c` from [installer source commit `32afcd4cd534d8e2f99ae76aa0234a0a5c697ba9`](https://github.com/proxmox/pve-installer/tree/32afcd4cd534d8e2f99ae76aa0234a0a5c697ba9). The custom launcher takes over before its DHCP/SLAAC/chronyd tail. The builder pins the actual initrd and boot configuration, removes alternate stock boot paths, preserves boot records and reads back mapped output content. It modifies only the installer layer, retaining the base layer and its Python runtime.

The direct adapter refreshes the official low-level installer's read-only environment/udev records and proves the disk and management selectors before passing an in-memory answer to the automated frontend. Upstream storage installation remains responsible for partitioning. Exit zero alone is insufficient: the adapter requires the explicit upstream completion records and fresh target-root/LVM ancestry before staging.

See [installer implementation and qualification](installer-qualification.md) for actual source hashes, tested transformation boundaries and outstanding Linux assembly/boot checks. No installer assistant package was downloaded through unauthenticated APT, no certificate validation was disabled and no disk installation was performed here. Source matching and filesystem inspection do not qualify execution.

## Qualification and redistribution gates

Use the initial disposable lab allocation of 4 vCPU, 16 GiB RAM and a 128 GiB disk. The lock's individual host/VM budgets are provisional starting allocations, not published minimum requirements. Account for downloaded and expanded media, temporary installer space, guest disks and measured peak use before qualifying any budget. The profile and budgets remain `unqualified`; an explicit disposable qualification build may use them, but a release publisher must refuse them.

The narrow M0 gate requires a verified complete Proxmox ISO; the exact shipped source/runtime match; actual ISO extraction/rebuild tools; and a disposable x86-64 Linux KVM runner with UEFI, independent target/canary disks, management peer and DHCP/RA WAN peer. Capture startup traffic to prove no host WAN address is acquired. Hash every disk before/after cancellations and refusal cases, including non-target conflicting storage. Prove that successful staging survives USB removal and that leaving USB inserted cannot reinstall. Run interrupted-staging and no-upstream boots. Missing tools, hardware or evidence must report **NOT RUN**, never PASS. Physical two-port testing remains a separate gate after the disposable lab succeeds.

Before redistribution, collect the exact shipped copyright/license notices and corresponding-source obligations for the full Proxmox, OPNsense and Ubuntu distributions; each contains software under multiple licenses. Preserve the upstream Restic source and license notice at its pinned release. The current `source` links identify upstream projects; they are not a complete source archive or a completed redistribution inventory. No public release or complete V1 claim is authorized by this input record.
