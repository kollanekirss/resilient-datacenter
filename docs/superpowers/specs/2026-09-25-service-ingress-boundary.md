# Private service ingress boundary

Application HTTPS currently binds to the overlay address, but a LAN route to that address can bypass overlay membership. Add a narrowly owned nftables input table before either application proxy starts. Drop TCP 443 destined to the verified overlay IPv4 unless the actual input interface is tailscale0 or lo. Source-address claims and forwarded HTTP headers do not grant access. Existing institutional firewall decisions remain effective; do not flush or change other tables. Regional LAN 8443 endpoints retain their separate peer/path constraints.

Keep this check in the already frozen shared application runtime. Require exact table, chain, expression and ownership-comment structure; refuse to replace unexpected rules. Check during readiness and create atomically only when absent. Install the nftables package without enabling a generic firewall service. Ordinary proxy restart, repeat installation, upgrade and fresh restore must reestablish the rule before publishing. Do not modify backed-up application configuration or accept arbitrary historical helper revisions.

Acceptance: unit rejection of unexpected/missing/changed rules; actual disposable Linux namespace denial of LAN and spoofed overlay-source ingress, ordinary loopback and overlay-interface access; real application and regional regression checks. The upgrade maintenance fixture uses an explicitly synthetic tailscale0 interface to distinguish normal overlay ingress from the stronger maintenance block. Actual VPN traffic remains covered by regional and home-NAT acceptance. Root tampering and physical routers are outside this boundary.
