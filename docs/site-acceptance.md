Use the exact proposed release with disposable accounts/data. This worksheet records evidence still required beyond the automated Ubuntu tests. Leave an unperformed item as **NOT RUN**, not “passed by design.” Do not simulate a public-provider result or a colleague's experience.

## Perform and record

| Exercise | Expected outcome | Result and measured evidence |
|---|---|---|
| Fresh personal installation behind the actual home router | Outbound enrollment, no public management SSH, trusted HTTPS and a real message/file operation | NOT RUN |
| Institutional package setup | Separate chat/file VMs, accounts, denied other-user access and approved sharing | NOT RUN |
| Actual DNS-provider issuance and renewal | Trusted leaf issued/replaced; simulated credential failure retains current leaf and is visible | NOT RUN |
| Offsite snapshot | Full application capture reaches separate storage; age, destination and independent recovery access recorded | NOT RUN |
| Primary-site shutdown | Old primary independently fenced; selected snapshot age recorded before promotion | NOT RUN |
| Fresh replacement recovery | Original network/application identity restored; measured time includes provisioning/download; login and selected data verified | NOT RUN |
| Encrypted chat recovery | Fresh user client recovers encrypted history using independently held user recovery key | NOT RUN |
| One relay/site unavailable | Approved traffic resumes through an independently placed surviving path; outage measured | NOT RUN |
| Controller unavailable and recovered | Existing useful traffic tested separately from enrollment; recovered authority accepts a new node | NOT RUN |
| Cable/upstream or regional loss | Record actual surviving routes; internal operations checked, delayed sharing/backup made visible | NOT RUN |
| Two institutions and one regional network | Approved exchange succeeds; unrelated node, admin routes and withdrawn partnership are denied | NOT RUN |
| Reviewed application upgrade | Actual eligible predecessor, maintenance, current-version backup and recovery verified | NOT RUN |
| Unfamiliar colleague | Person follows only released instructions, records every unclear step, completes installation and recovery | NOT RUN |

A single sea-cable cut is not necessarily total isolation: the outcome depends on real alternate routes, providers and power. Record the observed failure, surviving dependencies, user-visible interruption and unavailable features. Do not intentionally interrupt production infrastructure for a pilot exercise.

For each recovery, record the snapshot capture time, last known user write, outage/fencing time, start of replacement preparation, service verification time and successful user-operation time. The selected capture time defines the recoverable data window. State which later writes were lost; never report service verification alone as complete recovery.

## Promotion decision

The operator and reviewer compare results with the agreed targets and the product's advertised journeys. Failed or missing items block claims covering those items. Store a sanitized public summary separately from private operational details. A supported institutional release also needs the institution's security/governance review and ongoing maintenance ownership; this project does not certify them.
