# 0.4.0-dev.3 — portable local applications

Development source iteration; no signed release artifact or production-readiness claim.

The portable wizard gains step 9: a private, reproducible application kit and
instructions for separate NGINX, Synapse/Element and Nextcloud VMs. Guarded local
commands install the application profile without Headscale/Tailscale enrollment.
Local users use permanent service names, prepared TLS trust and local accounts.
The existing overlay deployment keeps its defaults.

NGINX uses verified HTTPS to literal backend addresses, replaces forwarding
headers and rejects unknown or inconsistent hostnames. Backends restrict HTTPS
to the fixed frontend source. Owned firewall rules return before service startup;
configuration drift is refused. Certificate preparation validates the trust path
at the end of the planned offline window. Frontend renewal retains the preceding
generation and supports recovery from an interrupted activation.

Portable snapshots and controlled-upgrade ownership preserve the exact access
identity. Native restore isolates LAN ingress without waiting for an overlay.
The backup source can use an independently prepared private SFTP destination;
the legacy backup-target installer still requires overlay enrollment.

Read the [local application guide](../portable-local-applications.md).

## Validation

The local suite passes **784 tests**, plus all Ansible syntax and read-only
host/task checks. Documentation links and whitespace checks pass.

Both portable packages passed on source `bba8ba8` in
[run 36195561861](https://github.com/kollanekirss/resilient-datacenter/actions/runs/36195561861).
Actual NGINX, Synapse/Element and Nextcloud were exercised with separate frontend,
staff and same-bridge attacker endpoints. The tests verify real login/message and
file operations, forged-header handling, hostname/TLS refusal, direct-backend
denial, frontend certificate replacement and repeated renewal. With external
traffic blocked, they stop/restart services, recreate ingress guards and restore
native application snapshots; saved data remains and later writes are removed.
No Tailscale daemon or substitute was installed.

This is protocol-client acceptance, with locally served Element HTML/configuration;
a full browser journey on the combined physical kit is still required. The new
snapshot exercise uses a local native snapshot, not an encrypted SFTP transfer.
Existing encrypted transport, browser, federation, upgrade and fresh-guest
regression workflows remain separate checks on [PR #21](https://github.com/kollanekirss/resilient-datacenter/pull/21).
Portable upgrade ownership/rollback has unit coverage; live adjacent-version
migration remains covered by the existing overlay upgrade fixture.

Acceptance and review caught firewall metadata ordering, a proxy placeholder,
combined-versus-network ownership in restore verification, and JSON render order.
The test-only Nextcloud address probe was updated for its supported request API.
No server software ran on the preparation Mac.

## Remaining gates

The Linux acceptance fixture tests one application at a time with NGINX and
clients on separate network endpoints. It does not boot a complete Proxmox kit
or exercise OPNsense routing, DHCP or a physical loss of power. Application
restoration reuses installed software and prepared TLS; a full empty-host offline
rebuild remains stage 5. Portable regional federation, changed-uplink relocation
and domestic bootstrap recovery remain stage 6. Physical capacity/power and an
unfamiliar colleague's installation/recovery exercise remain stage 7.

Review is by the implementing author. No independent security review or
institutional production acceptance is claimed.
