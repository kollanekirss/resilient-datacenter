# 0.4.0-dev.1 — modular guest-installation wizard

Development source iteration; no signed binary release or production-readiness claim.

Start with `rdc start --platform proxmox`. The guided journey prepares a private site plan, checks and allocates stopped VM shells, downloads pinned Ubuntu/OPNsense media, uploads it with a server-side checksum and manages isolated console installation for the six planned roles. Guest progress survives quitting and resuming.

Installation remains guided through each VM's Proxmox console. The wizard records installation and successful login as operator attestations, separately from its observations of VM power state and disk-only boot configuration. It does not claim an automatic in-guest OS health probe.

All NICs remain disconnected. OPNsense policy, Unbound, NGINX and the application configuration are the next phase. No existing guest is overwritten, no disk is deleted, no host bridge is reconfigured and no uncertain installer-start request is automatically replayed.

Verification: 703 local tests and all local Ansible syntax/read-only task checks passed for this iteration. Test-first coverage exercises media tampering/expansion limits, private state, checksum-bearing multipart upload, uncertain API responses, phase/ownership/drift checks, corrupt journals and wizard preparation/resume. Author review fixed misleading completion wording, malformed-journal handling and stale media-catalogue receipts. This was not independent review.

Actual vendor-media download verification runs separately on a disposable GitHub Ubuntu runner. Live Proxmox upload/configuration/boot, both console installers, physical hardware and disconnected application acceptance remain NOT RUN without a test host.
