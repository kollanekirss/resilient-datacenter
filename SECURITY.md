# Security reporting

This project is experimental and has no production-supported release or guaranteed security response time. Do not deploy sensitive institutional data before your own review and acceptance. Pin reviewed source and component versions; publication and signed provenance are not a security audit.

Report a suspected vulnerability through [GitHub private vulnerability reporting](https://github.com/kollanekirss/resilient-datacenter/security/advisories/new). Private reporting is enabled for this repository. Include the affected commit/release, supported operating system, required access, impact and minimal reproduction with synthetic data. Never include real recovery keys, passwords, enrollment links, private inventories or user content. Do not open a public issue with exploit details or test against another organisation's infrastructure.

If the private form is unavailable, do not publish sensitive details. A public issue may state only that a private reporting channel is needed. No alternate confidential email address has been published.

Operators should retain independent console access, separate administration identities, narrowly granted network/application permissions and recovery credentials outside the affected site. The guided backup writer can delete its repository; encryption is not immutability. Physical security, host patching, alerting and institutional incident response remain operator responsibilities.
